## DA-005 · Supabase schema + RLS

**Goal:** A local Supabase with the full user-data schema from `docs/architecture.md`, locked down by Row Level Security, with generated TypeScript types.

**Context:** `docs/architecture.md` (Data model, Auth flow, Security checklist), `docs/gamification.md`

**Prerequisites (Enes):** Docker Desktop running. The Supabase CLI runs through `npx supabase`, so no global install is needed.

**Scope**
1. `npx supabase init`. In `supabase/config.toml`, enable anonymous sign-ins (`[auth] enable_anonymous_sign_ins = true`).
2. One migration, `supabase/migrations/<timestamp>_initial_schema.sql`, creating:

   | Table | Columns and constraints |
   |---|---|
   | `profiles` | `id uuid PK references auth.users on delete cascade`, `display_name text`, `weekly_goal_days smallint not null default 4 check (weekly_goal_days in (3,4,5,7))`, `ui_language text not null default 'en'`, `created_at timestamptz not null default now()` |
   | `lesson_progress` | `user_id uuid references auth.users on delete cascade`, `lesson_id text`, `best_score smallint not null check (0–100)`, `attempts int not null default 1`, `completed_at timestamptz not null default now()`, PK `(user_id, lesson_id)` |
   | `theme_checks` | `id bigint generated always as identity PK`, `user_id`, `theme_id text`, `score smallint check (0–100)`, `taken_at timestamptz default now()` |
   | `review_cards` | `user_id`, `word_id text`, `due timestamptz not null`, `stability double precision`, `difficulty double precision`, `elapsed_days int`, `scheduled_days int`, `reps int default 0`, `lapses int default 0`, `state smallint check (0–3)`, `last_review timestamptz`, PK `(user_id, word_id)` |
   | `review_logs` | `id bigint identity PK`, `user_id`, `word_id text`, `rating smallint check (1–4)`, `reviewed_at timestamptz default now()` |
   | `activity` | `user_id`, `day date`, `xp int default 0`, `lessons int default 0`, `reviews int default 0`, PK `(user_id, day)` |

   - Every `user_id` is `uuid not null references auth.users(id) on delete cascade`.
   - Indexes: `review_cards (user_id, due)`, `review_logs (user_id, reviewed_at)`, `theme_checks (user_id, theme_id)`.
   - A trigger function `handle_new_user()` that inserts a `profiles` row on every insert into `auth.users` (anonymous users included). Use `security definer` with `set search_path = ''`.
3. **RLS** enabled on every table. Policies per table for `select`, `insert`, `update` and `delete`, all `to authenticated` with `using / with check ((select auth.uid()) = user_id)` (`id` for `profiles`). `review_logs` gets no update or delete policy, because logs are append-only.
4. Scripts: `db:start` (`supabase start`), `db:stop`, `db:reset` (`supabase db reset`), `db:types` (`supabase gen types typescript --local > src/lib/supabase/database.types.ts`).
5. Commit the generated `database.types.ts`.
6. Add `.env.example` with `NEXT_PUBLIC_SUPABASE_URL=` and `NEXT_PUBLIC_SUPABASE_ANON_KEY=`, each with a comment saying where `supabase start` prints it. If the CLI prints a *publishable key* instead of an anon key, use that and name the variable to match.
7. Add `.env.local` to `.gitignore` if it isn't covered already.
8. Update the README Quick start if any command differs.

**Out of scope**
- Supabase client code in the app (DA-030)
- Automated RLS tests (DA-033). Do the manual check below instead.
- A cloud Supabase project

**Acceptance criteria**
- [ ] `npm run db:reset` applies the migration from scratch with no errors
- [ ] `select tablename, rowsecurity from pg_tables where schemaname = 'public'` shows `true` for all 6 tables
- [ ] Manual check, with the steps written in the PR: as anonymous user A, insert a `lesson_progress` row; as anonymous user B, `select` returns 0 rows and `update` of A's row affects 0 rows
- [ ] Creating an anonymous user creates a `profiles` row
- [ ] `database.types.ts` is generated and `npm run typecheck` passes

**Notes**
- The schema stores **user data only**. Content IDs (`lesson_id`, `word_id`, `theme_id`) are strings pointing at the JSON in `content/` (ADR-002). No foreign keys to content.
- Column names for `review_cards` match the `ts-fsrs` `Card` fields so DA-040 maps them 1:1. Check the installed `ts-fsrs` docs if a field name differs, and say so in the PR.
