## DA-007 · UI primitives

**Goal:** The 7 design-system components exist as typed, accessible React components that look exactly like the design system previews.

**Context:** `docs/design-system/components/*/README.md` (props, states, rules), `docs/design-system/components/*/preview.html` and `reference.css` (the exact look), `docs/gamification.md` (mastery levels)

**Scope:** In `src/components/ui/`, one folder per component with `<Name>.tsx`, `<Name>.test.tsx` and `index.ts`:

| Component | Props (minimum) | Key states |
|---|---|---|
| `Button` | `variant: 'primary' \| 'secondary' \| 'ghost'`, `block?`, native button props, `asChild?` or a separate `ButtonLink` for links | press-down on `:active`, disabled |
| `ThemeTile` | `number`, `name`, `level: -1 \| 0 \| 1 \| 2 \| 3 \| 4`, `isCurrent?`, `href?` | locked, 0–4 corners glazed (clockwise from top-left), mastered medallion, current outline |
| `WeeklyGoalRing` | `goalDays: 3 \| 4 \| 5 \| 7`, `doneDays`, `weeksOnTrack`, `title`, `subtitle` | one segment per goal day |
| `AnswerOption` | `label`, `index`, `state: 'idle' \| 'selected' \| 'correct' \| 'incorrect'`, `onSelect` | check icon + "Goed", cross icon + "Fout" |
| `FeedbackSheet` | `result: 'correct' \| 'incorrect'`, `headline`, `correctAnswer?`, `explain?`, `xp?`, `actionLabel`, `onContinue` | `aria-live="polite"`, focus moves to the button |
| `WordTile` + `InlineWord` + `Gloss` | `word`, `wordId`, `state`, `onSelect`; Gloss: `article?`, `plural?`, `meaning`, `onPlay`, `onAddToReview` | placed, saved, active, speaking |
| `LessonBar` | `total`, `results: ('done' \| 'missed')[]`, `currentIndex`, `xp`, `onClose` | segmented, `role="progressbar"` |

Also:
- The **mastery-to-corners mapping** is a pure function, `src/features/progress/tile.ts` (`cornersForLevel(level) → boolean[4]`), with tests. `ThemeTile` uses it.
- Put `UNLOCK_NEXT_THEME_AT = 'practiced'` in `src/features/progress/config.ts` with a comment saying the PO may switch it to `'started'`. It's not used yet; DA-051 will use it.
- A dev-only page at `/dev/components` that renders every component in every state, like the design system previews.

**Out of scope**
- Real data, routing or Supabase
- Animations beyond the press and the 200ms sheet rise (respect `prefers-reduced-motion`)
- Drag-and-drop for word tiles (DA-022)

**Acceptance criteria**
- [ ] Each component matches its `preview.html` in light and dark. Put side-by-side screenshots in the PR.
- [ ] Only token-based Tailwind utilities. No hex colours, no arbitrary values unless commented with a reason.
- [ ] Tests cover at least: ThemeTile (corners per level; the accessible name includes the state text), WeeklyGoalRing (segment count = `goalDays`, filled = `doneDays`), AnswerOption (correct and incorrect show an icon and a word), FeedbackSheet (focus moves to the button), LessonBar (`aria-valuenow`)
- [ ] Keyboard: everything reachable with Tab, visible focus ring, AnswerOption selectable with keys 1–4 via an `onKeyDown` on the group (document how a parent wires it)
- [ ] Lint, typecheck, tests and build pass

**Notes**
- Size L. If the PR gets above roughly 800 changed lines, split it into two PRs (Button, ThemeTile, WeeklyGoalRing, LessonBar first; then AnswerOption, FeedbackSheet and the word components) and say so.
- Icons are inline SVGs for now (check, cross, close, speaker). Lucide comes later, if we need more.
