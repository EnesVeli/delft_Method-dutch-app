## DA-006 · Design tokens + fonts

**Goal:** The *Delft Dutch* design system is available in the app as CSS variables and Tailwind utilities, generated from one source file and working in light and dark.

**Context:** `docs/design-system/README.md`, `docs/design-system/tokens.json`, `docs/design-system/reference.css`

**Scope**
1. `scripts/build-tokens.ts` (run with `tsx`) reads `docs/design-system/tokens.json` and writes `src/styles/tokens.css`:
   - `:root { … }` with every colour and shadow token's **light** value, plus spacing and radius
   - `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { …dark values… } }`
   - `:root[data-theme="dark"] { …dark values… }`
   - Aliases (`"{delft}"`) become `var(--delft)`
   - A header comment: `/* GENERATED from docs/design-system/tokens.json by npm run tokens. Do not edit. */`
2. Script `tokens` runs the build. Commit the generated `tokens.css`.
3. Map the tokens to Tailwind v4 in `src/app/globals.css` with `@theme inline`: `--color-<name>: var(--<name>)` for every colour, plus `--radius-*`, `--shadow-*` and `--spacing` where it fits. The result is utilities like `bg-surface-raised`, `text-ink-muted`, `border-line-strong`, `rounded-tile`, `shadow-press`.
4. Type styles as Tailwind `@utility` classes, named and sized exactly as in `tokens.json`: `text-display-xl`, `text-display-lg`, `text-title`, `text-stat`, `text-lesson`, `text-body`, `text-body-strong`, `text-caption`, `text-label` (uppercase plus letter-spacing).
5. Fonts through `next/font/google`: Bricolage Grotesque (weights 600 and 700, `opsz` axis) and Atkinson Hyperlegible (400 and 700). Expose them as `--font-display` and `--font-sans` with the fallback stacks from `tokens.json`. The body uses `font-sans`, `bg-surface` and `text-ink`.
6. A dev-only page at `/dev/tokens` (calls `notFound()` in production) that shows every colour swatch with its name, every type style, the radii and the shadows. Used to check the port visually.
7. Unit test for the token script: given a small `tokens.json` fixture, the output contains the light value in `:root`, the dark value in both dark blocks, and an alias as `var(--…)`.

**Out of scope**
- Components (DA-007)
- A theme toggle UI. We follow the system theme for now; `data-theme` is supported for later.

**Acceptance criteria**
- [ ] `npm run tokens` regenerates `tokens.css` byte-for-byte identical (idempotent)
- [ ] `/dev/tokens` matches the design system's colours in light **and** dark (screenshots of both in the PR)
- [ ] No hex colour appears anywhere in `src/` except the generated `tokens.css`. Add a grep check for this to the `lint` script.
- [ ] Fonts load with no layout shift, and fallbacks are declared
- [ ] Lint, typecheck, tests and build pass

**Notes**
- `tokens.json` is the single source of truth. If a value looks wrong, flag it in the PR. Don't change it in CSS.
