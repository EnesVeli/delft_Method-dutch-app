## DA-004 · CI pipeline

**Goal:** Every PR into `v2` (and later `main`) is checked automatically, and nothing merges red.

**Context:** `docs/architecture.md` (CI), `docs/roadmap.md` (Definition of Done)

**Scope**
1. Add `.github/workflows/ci.yml`. It runs on `pull_request` to `v2` or `main`, and on `push` to `v2` or `main`.
2. **Job `check`** (ubuntu-latest, Node from `.nvmrc`, npm cache): `npm ci`, then `format:check`, `lint`, `typecheck`, `test` and `build`, each as a named step.
3. **Job `e2e`** (needs `check`): `npm ci`, `npx playwright install --with-deps chromium`, `npm run test:e2e`. Upload `playwright-report/` as an artifact when the job fails.
4. Use `concurrency` so a new push cancels the previous run on the same branch.
5. Add a CI status badge to `README.md`, under the title.
6. Add `.github/pull_request_template.md` with the PR template from `CLAUDE.md`.

**Out of scope**
- Deploy previews (Vercel does these itself once connected)
- Content validation step (added in DA-011)
- Branch protection rules. Enes sets these in GitHub settings: require `check` and `e2e` to pass before merging into `v2`.

**Acceptance criteria**
- [ ] The PR for this ticket shows both jobs passing
- [ ] A deliberately broken commit (for example a type error) makes `check` fail. Push it, confirm, then revert it in the same PR.
- [ ] The badge renders on GitHub

**Notes**
- Keep the workflow readable. Two jobs, no matrix, no custom actions.
